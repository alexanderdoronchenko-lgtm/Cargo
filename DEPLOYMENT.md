# Деплой: бот + Mini App + BotFather

## 1. Установка бота на сервере (systemd)

`scripts/deploy_bot.sh` — идемпотентный скрипт для Debian/Ubuntu: ставит
системные пакеты (`git`, Python 3.10+, `libcairo2` для рендера досок,
`stockfish`, `cron`), клонирует нужную ветку в `/opt/cargo-bot`, заводит
отдельного системного пользователя (бот никогда не работает от root),
создаёт venv и ставит зависимости, пишет `.env` (не коммитится в git) и
настраивает systemd-юнит `cargo-bot.service` с автозапуском при загрузке
сервера и автоперезапуском при падении (`Restart=on-failure`). Секреты в
самом скрипте не хардкодятся — только имена переменных.

Бот работает через long polling (`dp.start_polling`), поэтому открывать
входящий порт на сервере не нужно.

Запуск на сервере (от root):

```
BOT_TOKEN=<токен от @BotFather> \
ANTHROPIC_API_KEY=<ключ Claude API> \
ADMIN_USER_ID=<твой Telegram user_id> \
./scripts/deploy_bot.sh
```

Повторный запуск того же скрипта безопасен — подтягивает новый коммит из
ветки, обновляет зависимости и перезапускает сервис, ничего не дублирует
(включая cron-задачу из шага 5).

Этот шаг **не трогает** Mini App, Nginx или SSL — это отдельные шаги 2-4
ниже, для них нужен домен (см. DEPLOYMENT для Mini App).

Проверить: `systemctl status cargo-bot` → `active (running)`;
`journalctl -u cargo-bot -f` — логи бота; бот должен отвечать на `/start`
в Telegram.

## 2. Задеплоить Mini App и получить HTTPS-адрес

Telegram принимает только `https://` для `web_app` — обычный http не пройдёт
ни в кнопке, ни в BotFather. Нужен домен, чей A-record уже указывает на
сервер — Let's Encrypt не выпускает сертификаты на голый IP.

`scripts/deploy_miniapp.sh` — идемпотентный скрипт, запускать **после**
`scripts/deploy_bot.sh` (шаг 1) на том же сервере: ставит Nginx, certbot и
Node.js (через NodeSource — версия из apt на большинстве
Debian/Ubuntu слишком старая для текущего Vite), собирает `miniapp/`
(`npm ci && npm run build`, с `VITE_API_BASE_URL=https://<домен>`),
заводит systemd-юнит `cargo-api.service` для API (`uvicorn`,
слушает только `127.0.0.1:8000`, наружу не торчит), настраивает Nginx
(статика `miniapp/dist/` на `/`, реверс-прокси `/api/` → `127.0.0.1:8000`,
`index.html` — `Cache-Control: no-store, must-revalidate` чтобы клиент
всегда подтягивал свежий HTML со ссылками на актуальные хэши сборки,
`/assets/` — агрессивный `immutable`-кэш на год, так как у файлов Vite
хэш меняется на каждой сборке и старая версия просто никогда больше не
запрашивается; это важно из-за отдельного известного бага: встроенный
WebView Telegram кэширует HTML на своём уровне так, что штатная очистка
кэша в Telegram его не берёт — без этих заголовков обновление Mini App
не долетает до уже открывавших его пользователей),
получает сертификат через `certbot --nginx` (сам добавляет HTTPS-блок и
редирект с http на https), **сам прописывает `MINIAPP_URL` в `.env` бота
и перезапускает `cargo-bot`** — шаги 3-4 ниже он покрывает автоматически.

Запуск на сервере (от root):

```
DOMAIN=coachgm.online \
LETSENCRYPT_EMAIL=<твой email для уведомлений об истечении сертификата> \
./scripts/deploy_miniapp.sh
```

Повторный запуск безопасен — пересобирает фронтенд, обновляет Nginx-конфиг,
certbot не переиздаёт сертификат раньше времени сам по себе.

Проверить: `curl https://<домен>/` → отдаёт `index.html`;
`curl -I https://<домен>/` → заголовок `Cache-Control: no-store, must-revalidate`;
`curl -sI https://<домен>/assets/$(curl -s https://<домен>/ | grep -oP 'assets/\K[^"]+\.js' | head -1)`
→ `Cache-Control: public, max-age=31536000, immutable`;
`curl https://<домен>/api/audio/tracks` → JSON, не 502;
`systemctl status nginx cargo-api cargo-bot` → все `active (running)`.

## 3. `MINIAPP_URL` в `.env` бота

Если сервер разворачивался через `scripts/deploy_miniapp.sh` (шаг 2) — это
уже сделано автоматически, вместе с перезапуском бота. Дальше — что именно
происходит и как поправить вручную (например, при деплое без скрипта).

```
MINIAPP_URL=https://<твой-реальный-домен>/
```

Сейчас там placeholder (`https://example.com/critical-moment-miniapp`) —
бот с ним прекрасно стартует и кнопки показываются, просто по нажатию
откроется не то. Замени на настоящий адрес и перезапусти бота
(`systemctl restart cargo-bot`) — кнопка в `/puzzles` и в меню чата сразу
начнут открывать реальное приложение, никаких других правок в коде не нужно.

## 4. BotFather: `/newapp`

Это единственная часть, которую нельзя сделать через код — регистрация Mini
App делается только вручную через диалог с @BotFather.

1. Открой чат с **@BotFather**.
2. Отправь `/newapp`.
3. Выбери бота, к которому привязываешь Mini App (если бот один — BotFather
   предложит его сразу).
4. **Title** — название приложения, которое видит пользователь (например,
   `Critical Moment`).
5. **Description** — короткое описание (пара предложений).
6. **Photo** — иконка/превью приложения, PNG или JPG, **640×360**.
7. **GIF-демо** — необязательно, можно пропустить командой `/empty`.
8. **Web App URL** — тот же самый адрес, что прописан в `MINIAPP_URL` в
   `.env` (шаг 3). Это ключевой момент: URL здесь и в `.env` должны совпадать
   — иначе кнопка в боте и прямая ссылка `t.me/<бот>/<short_name>` будут
   вести на разные версии приложения.
9. **Short name** — короткий идентификатор для прямой ссылки
   (`t.me/<бот>/<short_name>`), например `puzzles`. Только латиница, цифры,
   подчёркивания.
10. BotFather подтвердит создание и покажет прямую ссылку на приложение.

После этого Mini App появится в меню вложений бота (иконка «+» в чате) сама,
без дополнительных действий.

### Кнопка в чате (persistent menu button)

Отдельно от `/newapp`, бот **уже сам** настраивает постоянную кнопку слева
от поля ввода (через `bot.set_chat_menu_button()` в `bot.py`, при каждом
старте) — она тоже откроет `MINIAPP_URL`. Ничего вручную делать не нужно,
но если захочешь другой текст на кнопке или управлять этим из BotFather, а
не из кода — это `/mybots` → выбрать бота → *Bot Settings* → *Menu Button*.
Что бы ни было настроено последним (код при рестарте бота или BotFather
вручную) — то и будет действовать, это одна и та же настройка с двух
разных концов.

## Проверить, что всё подключено

- `/puzzles` в боте → должна прийти кнопка, открывающая настоящее
  приложение (не example.com).
- Кнопка слева от поля ввода в чате с ботом → то же самое.
- `t.me/<бот>/<short_name>` (из шага 9) → должна открывать то же
  приложение напрямую, в обход бота.

## 5. Автобэкап SQLite-базы (cron)

Если сервер разворачивался через `scripts/deploy_bot.sh` (шаг 1) — эта
cron-задача уже настроена автоматически, для пользователя `cargo`.
Проверить: `sudo -u cargo crontab -l`. Дальше в этом разделе — что именно
настроено и как добавить/поправить эту задачу вручную (например, при
деплое без скрипта или под другим пользователем/путём).

`scripts/backup_db.py` раз в день снимает консистентный снапшот `.db`-файла
в `backups/db_<дата>.sqlite` (например `backups/db_2026-08-15.sqlite`) и
хранит только последние 7 копий — более старые удаляются автоматически при
каждом запуске. Снимок делается через встроенный в sqlite3 online-backup
(`sqlite3.Connection.backup()`), а не простым копированием файла — это
безопасно даже пока бот держит базу открытой на запись; обычный `cp` в этот
момент мог бы скопировать файл в середине транзакции и получить битую копию.

Скрипт не импортирует `config.py` (там обязательны `BOT_TOKEN` и
`ANTHROPIC_API_KEY`) — бэкап базы не имеет отношения к этим ключам, поэтому
путь к базе читается из `.env` напрямую (та же переменная `DB_PATH`, что
использует сам бот; без неё — `bot.db` в корне проекта).

Настройка на сервере:

```
crontab -e
```

Добавить строку (раз в день в 3:00 по времени сервера):

```
0 3 * * * cd /путь/к/Cargo && /usr/bin/python3 scripts/backup_db.py >> backups/backup.log 2>&1
```

Замени `/путь/к/Cargo` на реальный путь деплоя. Если `DB_PATH` в `.env`
указывает на нестандартное расположение — скрипт подхватит его сам (он
читает тот же `.env`); при необходимости путь к базе и к папке с бэкапами
можно передать явно: `python3 scripts/backup_db.py /путь/к/bot.db /путь/к/backups`.

`backups/` уже в `.gitignore` — в бэкапах реальные данные пользователей, в
git они попадать не должны.

Проверить, что всё настроено: `python3 scripts/backup_db.py` из корня
проекта должен создать `backups/db_<сегодняшняя-дата>.sqlite` без ошибок;
`crontab -l` должен показывать добавленную строку.
